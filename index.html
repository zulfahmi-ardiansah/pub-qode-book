01

Why do we need two codebooks?

A company registration and a purchase order answer different questions. Codes help people organise and compare each kind of record, even when businesses use different names or descriptions.

For business activity

KBLI

Klasifikasi Baku Lapangan Usaha Indonesia
Indonesia’s business activity classification

What work does this business do?

KBLI provides common categories for activities such as farming, printing, and construction. Indonesia uses these categories in business registration and economic statistics, so similar activities can be recorded consistently.

For someone looking at a business record, the code helps identify its line of work. It does not give you that company’s product catalogue.

Example of an activity01111 · Pertanian Jagung (corn farming)

For purchasing

UNSPSC

United Nations Standard Products and Services Code
A classification of goods and services

What is being bought or sold?

UNSPSC gives buyers and suppliers a common way to classify catalogue items and purchases. Procurement teams can group similar spending and compare categories across suppliers instead of relying only on free-text item names.

For someone looking at a purchase, the code helps identify the kind of good or service. It does not tell you the supplier’s registered business activity.

Example of a product family50220000 · Cereal and pulse products

Working with both records means crossing from an activity to a product category. Neither codebook supplies that connection on its own.

The reason for Qodebook

A company is registered under KBLI 01111.
What would it actually be selling?

That is the practical question behind this project. The two classifications were made for different purposes. Looking up a business activity still leaves you with the work of finding plausible goods or services on the purchasing side.

Matching them by hand is a large job. The repository includes 158,473 UNSPSC entries and 2,444 KBLI entries. Qodebook uses a language model to propose connections, saves the results, and gives people a way to inspect them.

The aim is to make the comparison possible to investigate: read the definitions, follow the hierarchy, and decide whether a proposed link is useful for your case.

Motivation and catalogue sizes are documented in the project README. The counts describe the included data, not mapping accuracy.

What does a proposed link mean?

The mapping directly joins a five-digit KBLI activity (kelompok) to a UNSPSC family. It suggests a relationship to review. It does not prove that a particular company sells those goods or that every item in the family fits. The links are machine-generated, not an official correspondence table; some may be wrong.

How are the links made?

The mapper reads the activity with its parent hierarchy, then narrows UNSPSC choices through segment groups, segments, and families. A final filter keeps a family only if it can name a specific output the activity delivers. The reader labels links inherited from a family or collected from child activities. Read about the mapping process.

Put the codebooks to work

Read the data.
Check the connection.

The browser reader ships with its database. Run it locally to search both classifications and inspect the full set of stored links.

  • Search in English or IndonesianLook up a code, title, or definition and browse the hierarchy.
  • Understand the contextRead a code’s definition, parent, siblings, children, and links to the other classification.
  • Use the data elsewhereExport either codebook or the mapping as CSV or XLSX from the running app.

Start the browser reader

Docker includes Python, the app, and the database. From your terminal:

git clone https://github.com/zulfahmi-ardiansah/pub-qode-book.git
cd pub-qode-book
docker compose up --build

Then open http://localhost:8000 in your browser. An LLM API key is only needed if you run the mapper.

Run with Python instead

Use Python 3.13+ in your preferred environment. From the cloned repository:

python -m pip install -r requirements.txt
uvicorn serve.app:app --reload

Open http://127.0.0.1:8000. The committed SQLite database is ready to read.

Run the CLI mapper

Install the Python dependencies above. Copy .env.example to .env, set LLM_API_KEY, and configure an OpenAI-compatible endpoint and model. Then run:

python process/mapper.py

The mapper writes SQLite and skips activities that already have saved links. See the configuration and budget settings before generating new mappings.
